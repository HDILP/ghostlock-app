## 漏洞分析

### upstream fix (3bfdc63936dd)

| 旧代码 (有 bug)                   | 新代码 (修复后)                  | 影响                          |
|----------------------------------|--------------------------------|-------------------------------|
| `raw_spin_lock(&current->pi_lock)` | `raw_spin_lock(&waiter_task->pi_lock)` | 锁正确的 task |
| `current->pi_blocked_on = NULL` | `waiter_task->pi_blocked_on = NULL` | 清除正确的 PI 状态 |
| `..., current` in adjust_prio_chain | `..., waiter_task` | chain walk 用正确的 task |

### 已证明不可行的路径

#### 1. pi_waiters rb_erase (DEAD)
- Guard at 0x81ec0d0 要求 `w26=1`
- `w26=1` 需要 `lock == waiter_struct_pointer`，正常控制流下永远不成立
- Phase 4 的 crash 是 remove_waiter → tree_entry erase 的偶然，不是 pi_waiters 路径

#### 2. NFDS=320 pselect 覆写 — BUG_ON bypass 路径已识别
- vendor 在 `task_blocks_on_rt_mutex` (0x1ea860) 添加了 `BUG_ON(left_child->lock != waiter)` (3 处 brk #0x800)
- NFDS=128 copy 范围 = waiter+0x00..+0x2f → lock 字段(+0x38)不在范围内 → BUG_ON 不触发
- NFDS=320 copy 范围 = waiter+0x00..+0x4f → lock 字段在范围内
- **Bypass**: 设置 fd_set word 7 = waiter 的内核地址 → `waiter->lock = waiter`（自引用）
- 需要泄漏 waiter 的内核地址（KASLR-dependent）
- 详见 `docs/5.10-bugon-bypass.md`

#### 3. dangling pi_blocked_on UAF (DEAD)
- 理论：remove_waiter 清除 current 而非 waiter_task → waiter_task->pi_blocked_on 悬垂
- **实际情况**：`try_to_take_rt_mutex` (0x1ea4b8) 在 waiter_task 成功获取锁时清除其 `pi_blocked_on`
- Phase 6 实验验证：15/15 稳定无 crash
- waiter_task 返回 userspace 时 `pi_blocked_on = NULL`，不是悬垂指针

#### 4. KGSL GPU exploit (DEAD)
- CVE-2025-21479 exploit (cheese/FreeXR) 在设备上运行失败
- "can't get GPU r/w" — 漏洞已修补或 GPU pagetable 布局不兼容

### write-0 原语状态 (2026-08-19)

write-0 通过 pselect fd_set overlay 在 consumer waiter 的 tree_entry 上实现：
- pselect copy 将 fd_set word 2-4 写入 waiter+0x00..+0x17 (tree_entry)
- word 2 = (target-8)|1 → 设置 `__rb_parent_color` 指向 target-8
- rb_erase 在 consumer waiter 超时时触发，写 0 到 target

**已修复的 bug**：NFDS=128 时 word 3 映射到 waiter+0x08 (rb_right)，原始代码设 word 3=0 覆盖了 skb 中设置的 target 值。修复：`pselect_child_node ? 0 : target`。

**当前问题**：write-0 触发了 (calls=1, step=0) 但未命中 selinux_enforcing。enforce=1 持续。可能原因：target 地址计算有误，或 rb_erase 写入的实际地址偏移与预期不符。

## Dead-end paths (勿重复尝试)

1. **pi_waiters rb_erase** — guard w26=0 恒假，结构性不可达
2. **dangling pi_blocked_on** — try_to_take_rt_mutex 清除
3. **KGSL GPU r/w** — 漏洞已修补
4. **consumer tree_entry write** — rb_link_node 重置 rb_right/rb_left
5. **requeue waiter tree erase** — list guard 守卫

- adb 端口每次 panic 后变

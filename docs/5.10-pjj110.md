# 5.10 Port — OPPO Reno11 Pro (PJJ110)

> Experimental first 5.10 port of the GhostLock (CVE-2026-43499) exploit family.
> Status: **offsets verified from the actual kernel image; runtime untested on device.**

## Target

| Field          | Value                                        |
|----------------|----------------------------------------------|
| Device         | OPPO Reno11 Pro (PJJ110)                     |
| SoC            | Snapdragon 8+ Gen 1 (SM8475)                 |
| System         | ColorOS 15, PJJ11015.0.0.861(CN01B40P02)     |
| Kernel         | `5.10.226-android12-9-o-gbf90590695a1`       |
| Hardening      | PAC + SCS + Clang CFI + KASLR + KPTI         |
| Vuln status    | **Unpatched** — `remove_waiter()` uses `current` instead of `waiter->task` (fix = 5.10.261, upstream 3bfdc63936dd) |

## Why 5.10 needed hand-derived offsets

The Rust extractor (`tools/extract_rs`) requires BTF (`rt_mutex_waiter.pi_tree/wake_state`)
to derive `pselect_waiter_shift` and `struct_fields`. PJJ110's kernel has no BTF, so:

- symbol offsets (`off_init_task` … `off_slide_*`) came from extract_rs (kallsyms recovery) and
  were cross-checked against an independent kallsyms reconstruction (`vmlinux-to-elf`);
- struct offsets came from targeted disassembly of the shipped kernel
  (see `src/core/target.h` comments for the evidence chain).

## pselect_waiter_shift = -2 (frame-derived)

The freed `rt_mutex_waiter` and the pselect `stack_fds` buffer land at the **same**
kernel-stack offset:

```
futex chain:  __arm64_sys_futex(0x90) + do_futex(0x70) + futex_wait_requeue_pi(0x1a0)
              waiter @ sp+0x90  -> depth 0x210
pselect chain: __arm64_sys_pselect6(0xa0) + core_sys_select(0x1c0)
              stack_fds @ sp+0x50 -> depth 0x210
=> waiter == fd_set word 0  =>  shift = -2 (same convention as 6.6)
```

`src/core/fops.c` carries a 5.10 word map under `PSELECT_WORDS_V5_10` (no augment
prio/deadline, no wake_state — those fields do not exist in the 5.10 waiter struct).

## Notes / risks

- No BTF means the extractor's `--register` will emit a partial table; always hand-verify
  `struct_fields` on 5.10 builds.
- The write primitive relies on 5.10's plain `rb_erase` (6.x uses `rb_erase_cached`) —
  first runtime test may need primitive tuning.
- OPPO/ColorOS security stack (`oplus_secure_guard_new`, qsguard, oplus_theia/gaia) flags the
  SLIDE-stage `tgkill` signature. Use the two-phase strategy: run once during boot animation to
  cache KASLR (`kaslr_base.txt`), then run DIRECT after full boot.
- MSYS2 builds: use `-Wl,-dynamic-linker,//system/bin/linker64` (double slash) or the ELF
  `.interp` ends up as a Windows path and the binary dies with ENOENT.
